2D Godot Del 4 - Player Weapon

Nu har vi et rumskib der kan flyve rundt i rummet og det er jo meget fint men der sker ikke så meget og vi kan jo ikke forsvare os mod de fjender som snart kommer til at regne ned over os!

Lad os få rettet op på det og få lavet nogle kugler vi kan fyre af. Til det formål vil vi:

  1. Lave en ny Scene under vores Player som vi kalder PlayerBullet. Det skal være et Area2D med sprite og collision shape, og så skal vi lige kort lære om en ny node.
  2. Have at når vi trykker på Fire skal der laves en ny PlayerBullet der hvor vores rumskib nu er
  3. Have vores nye PlayerBullet til at flyve opad i skærmen så vi skal altså formindske y værdien.
  4. Sørge for at vi ikke bare kan fyre nye kugler afsted hele tiden, det ville være snyd!

Lad os komme igang

Det indledende arbejde

Du ved hvad du skal.

  • Ny mappe under Player som vi kalder PlayerBullet.
  • Ny Scene som også vi også kalder PlayerBullet, rod noden skal være Area2D og så skal vi have en Sprite2D og en CollisionsShape2D som child nodes. I assets mappen kan du finde bullet sprites i mappen Projectiles, du vælger selv.
  • Gem scenen som player_bullet.tscn i mappen PlayerBullet under Player.

Det skulle gerne se sådan cirka sådan her ud:

Vi skal lige have en ny ting med som vi ikke har brugt før.

Tilføj en VisibleOnScreenNotifier2D som child node til din PlayerBullet.

Den kan vi bruge til at få besked, når vores PlayerBullet kommer ind på skærmen eller når den forlader skærmen.

Det er super nyttigt for så kan vi slette vores kugle når den forlader skærmen, ellers ville vi bare stå og oprette kugler hele spillet igennem og vores spil ville bruge mere og mere RAM og blive langsomt, fordi det skulle holde styr på 10.000 kugler som forlængst havde forladt skærmen.

PlayerBullet Script

Nu er vi sådan set færdig med at bygge vores PlayerBullet scene, så skal vi have tilføjet et script. Vi vil (i første omgang) gerne tre ting.

  1. Vi vil flytte vores kugle hver gang _process funktionen bliver kaldt.
  2. Vi vil sætte vores kugle på skærmen der hvor vores rumskib er nu.
  3. Vi vil fjerne kuglen når den forlader skærmen.

Lad os oprette et nyt script og tage dem en af gangen.

Vælg PlayerBullet rod noden og tilføj et nyt script.

1. Flyt kuglen

At flytte vores kugle er væsentlig nemmere end det var at flytte vores rumskib, vi skal bare bevæge os opad på skærmen i en hastighed som vi har defineret. Prøv at se om du kan regne det ud selv inden du kigger på vores forslag.

@export var speed = 600.0

func _process(delta: float) -> void:
    position.y -= speed * delta

Vi definerer en hastighed og hver gang vi så skal gentegne kuglen i _process så rykker vi os opad i skærmen (tættere på 0)

2. Sæt kuglen

Vi vil gerne sætte kuglen på banen der hvor vores rumskib er nu. Derfor laver vi en funktion som vi kan kalde fra vores Player når der trykkes på Fire. Den skal sætte PlayerBullets Position til den værdi vi nu får ind. Det ser sådan her ud, stadig i PlayerBullet scriptet:

func start(pos: Vector2):
    position = pos

3. Slet kuglen

Vi vil gerne slette kuglen når den forlader banen, og til det skal vi bruge vores VisibleOnScreenNotifier2D. Den kan som sagt give os besked når vores kugle kommer ind på skærmen og når den forlader skærmen.

Lidt teori om Signaler

Til det bruger den noget, man i Godot kalder signaler. Det er første gang vi møder dem her, men det bliver ikke sidste gang!

Signaler fungerer ved at et objekt kan sende et signal, på engelsk emit a signal. Og det kan andre så lytte på og reagere på. I vores tilfælde er det VisibleOnScreenNotifier2D som emmitter signaler og dem vil vi så lytte på i vores script.

Signaler er super smarte for det giver os mulighed for at lytte på ting uden at skulle binde vores Scener alt for hårdt sammen. Omvendt kan det også blive noget værre rod med signaler på kryds og tværs, så man skal lige holde tungen lige i munden.

Og lad os så få slettet den kugle!

Nå, tilbage. Vælg VisibleOnScreenNotifier2D og kig i Inspectoren til højre. Lige til højre for Inspector står der Signals, klik på den fane

Som du kan se kan der sendes alle mulige signaler, både fra VisibleOnScreenNotitifer2D men også fra de super objekter som den nedarver fra (nedarv og super objekter er en historie til en anden gang)

Vi er interesserede i screen_exited() så den klikker vi på, og derefter på Connect… i bunden

Nu får vi en dialog op hvor vi kan vælge, hvad det er der skal have besked når vores kugle forlader skærmen.

Kig i dit PlayerBullet script. Nederst er der nu en funktion med det nemme navn

func _on_visible_on_screen_notifier_2d_screen_exited() -> void:
    pass # Replace with function body.

Og i venstre side ud for den er der en lille grøn pil der viser os at det er en funktion der er forbundet til et signal, du kan klikke på den lille grønne knap og se hvad det er vi er forbundet til…bare hvis du kom i tvivl.

Nå men fedt! Nu får vi besked når kuglen forlader skærmen…hvad vil vi så gøre med den information? Vi vil gerne kalde en funktion der hedder queue_free(). Som der står i dokumentationen for queue_free()

Queues this node to be deleted at the end of the current frame. When deleted, all of its children are deleted as well, and all references to the node and its children become invalid.

Så…vi forlader skærmen og beder vi om at få vores PlayerBullet slettet.

Det ser sådan her ud:

func _on_visible_on_screen_notifier_2d_screen_exited() -> void:
    queue_free()

Tada

Det var det i denne omgang. Nu er vores PlayerBullet en lille selvstændig ting som kan flyve op af skærmen fra en position og slette sig selv når den rammer kanten, smukt! Her er hele scriptet:

extends Area2D

@export var speed = 600.0

func start(pos: Vector2):
    position = pos

func _process(delta: float) -> void:
    position.y -= speed * delta

func _on_visible_on_screen_notifier_2d_screen_exited() -> void:
    queue_free()

Menøh…hvordan skyder vi så? Vi skal over i vores Player script og arbejde lidt videre.

Player Script

I vores Player script vil vi gerne:

  • Vide om der er trykket på Fire
  • Hvis der er, så sætter vi en kugle der hvor vi er lige nu

Herefter tager BulletScript over og kalder _process der sørger for at flytte kuglen, dvs.

  • Player scriptet har ansvaret for at sætte kuglen.
  • PlayerBullet scriptet har ansvaret for at flytte kuglen.

Lad os gå i gang.

Er der trykket fire?

I vores process lytter vi allerede på de forskellige retninger vi kan flytte os i, og vi opdaterer animationer.

Efter det kan vi tilføje:

if Input.is_action_pressed("fire"):
shoot()

Altså…er der trykket på fire (som vi definerede i en tidligere lektion), så kald funktionen shoot.

Sæt en kugle

Nu vil vi gerne lave en PlayerBullet fra vores Player…hvordan pokker gør vi det?

Vi skal have lavet en variabel af typen PackedScene i toppen af vores script. PackedScene betyder “en scene som er skrevet ned på disk” (og hvis I er ekstra fancy lads siger I, at det er en serialized scene…serialized betyder i computer sprog bare “skrevet ned på disk” men det lyder federe ikk’).

Det ser sådan her ud:

@export var player_bullet: PackedScene

Fordi vi har skrevet @export forrest kan vi nu binde vores PlayerBullet fast til den her variabel i Inspectoren så vælg 2D i toppen, find din Player scene og vælg Inspectoren i højre side. Du kan nu se en Player Bullet property som lige nu er <empty>

Nu kan du tage din player_bullet.tscn fil fra res mappen og trække den over og sætte den i feltet hvor der står <empty>, sådan at det nu ser sådan her ud:

Og med det er vores Player i stand til at lave nye PlayerBullets, så tilbage i Player scriptet med os.

Nu kan vi:

  1. Oprette en kugle
  2. Sætte kuglen i viewet
  3. Sætte kuglens position

Det ser sådan her ud:

func shoot():
    var bullet = player_bullet.instantiate()
    get_tree().root.add_child(bullet)
    bullet.start(position + Vector2(0, -32))

Vi kalder instantiate på vores player_bullet. Det er den måde man laver nye objekter på, vi siger at man instantierer en ny bullet.

Derefter får vi fat i view træet, rod noden og tilføjer vores bullet, nu er den på skærmen.

Til sidst kalder vi den start funktion vi lavede tidligere og sætter kuglens position = vores egen position og så lige 32 pixels op på y aksen så kuglen starter lidt foran vores skib.

Nu vil kuglen blive sat og så vil den ellers bare selv sørge for at flytte sig og så blive slettet når den forlader skærmen.

OK lidt snyd. Lad os introducere en “cooldown” timer, sådan at der lige går nogle milisekunder mellem hvert skud.

Cooldown Timer

Til det formål skal vi have tilføjet en Timer til vores Player, så det gør vi i Player scenen, kald den for GunCoolDownTimer. Timers er gode til at få noget til at ske enten.

  • En gang efter lidt ventetid
  • Flere gange med et mellerum

Og ventetiden kan være det samme tidsrum, eller forskellige tidsrum hver gang.

I Inspectoren skal du sætte den til at være One Shot, det betyder at den ikke selv starter igen når den har “fyret”, det skal vi nok selv styre.

![][image10]

Nu skal vi have tilføjet to variabler mere i vores PlayerScript

@export var gun_cooldown = 0.25
var can_shoot = true

gun_cooldown fortæller hvor længe vi skal vente mellem hvert skud og can_shoot er vores “flag” som vi bruger til at afgøre om vi kan skyde eller ej.

Lad os også lave en start funktion til vores player som vi kan bruge til at sætte alle sådan nogle ting op.

func start():
    can_shoot = true
    $GunCooldownTimer.wait_time = gun_cooldown
    position = Vector2(screen_size.x / 2, screen_size.y - 64)

$Boosters.play("default")

Her

  • Sørger vi for at vi kan skyde når spillet starter.
  • Sætter vi cooldown timeren til at “fyre” efter 0.25 sekunder.
  • Sætter vi vores position midterst, nederst på skærmen.
  • Starter vi booster animationen, den er flyttet op nede fra _process! Der er ingen grund til at starte den hver gang vi gentegner skærmen.

Og så tilbage til vores shoot funktion. Nu vil vi gerne

  • Starte med at se om man kan skyde, og hvis ikke man kan (fordi vi lige har skudt), så stopper vi bare med det samme.
  • Ellers sætter vi lige can_shoot til false så man ikke kan skyde
  • Starter cooldown timeren
  • Sætter skuddet som før

Så shoot ser nu sådan her ud:

func shoot():
    if not can_shoot:
        # Nope...too soon
        return

    # Flip the flag
    can_shoot = false

    # Start the timer
    $GunCooldownTimer.start()

    # Shoot
    var bullet = player_bullet.instantiate()
    get_tree().root.add_child(bullet)
    bullet.start(position + Vector2(0, -32))

Hvis du kørte scriptet nu, hvad ville der så ske? Eller…hvor mange gange kunne vi skyde?

En gang. Vi sætter can_shoot til false, men der er ikke noget der sætter den tilbage til true igen. Vi mangler at reagere på at vores timer løber ud. Her skal vi igen bruge et signal fra vores GunCooldownTimer så… vælg GunCooldownTimer og så find Signals.

Vi vil gerne connecte til timeout signalet så det vælger du, og trykker på Connect… i nederste højre hjørne.

Nu skulle du gerne få en signal funktion i bunden af dit Player script:

func _on_gun_cooldown_timer_timeout() -> void:
    pass # Replace with function body.

Tiden er gået, så det eneste vi vil her er at flippe can_shoot tilbage til true.

func _on_gun_cooldown_timer_timeout() -> void:
    can_shoot = true

Nyt Game Script

Nu er vi der næsten, men lad os bruge vores nye start funktion på Player fra vores Game så vi starter “ordentligt”, vi skal også bruge det til andre ting senere så vi kan lige så godt starte.

Du ved hvad du skal efterhånden.

Vælg Game scenen, stå på rod noden og tryk på den lille script knap.
I _ready() kalder vi bare $Player.start(). Sådan her ser vores Game script ud i sin helhed

extends Node2D

func _ready() -> void:
    $Player.start()

Kør dit spil igen og prøv at skyd. Nu går det knap så stærkt, vi er klar til fair kamp.

Her er det komplette Player script, hvis du har brug for at sammenligne:

extends Area2D

@onready var screen_size = get_viewport_rect().size
@export var speed = 400.0
@export var player_bullet: PackedScene
@export var gun_cooldown = 0.25

var can_shoot = true

var current_animation = ""

func start():
    can_shoot = true
    $GunCooldownTimer.wait_time = gun_cooldown
    position = Vector2(screen_size.x / 2, screen_size.y - 64)

    $Boosters.play("default")

# Called when the node enters the scene tree for the first time.

func _ready() -> void:
    pass # Replace with function body.

# Called every frame. 'delta' is the elapsed time since the previous frame.

func _process(delta: float) -> void:
    # Movement
    var input = Input.get_vector("left", "right", "up", "down")
    position += input * speed * delta
    position = position.clamp(Vector2(24, 24), screen_size - Vector2(24, 24))

    # Animations
    var next_animation = "forward"
    if input.x < 0:
        next_animation = "left"
    elif input.x > 0:
        next_animation = "right"

    if next_animation != current_animation:
        current_animation = next_animation
        $Ship.play(current_animation)

    if Input.is_action_pressed("fire"):
        shoot()

func shoot():
    if not can_shoot:
        # Nope...too soon
        return

    # Flip the flag
    can_shoot = false

    # Start the timer
    $GunCooldownTimer.start()

    # Shoot
    var bullet = player_bullet.instantiate()
    get_tree().root.add_child(bullet)
    bullet.start(position + Vector2(0, -32))

func _on_gun_cooldown_timer_timeout() -> void:
    can_shoot = true
